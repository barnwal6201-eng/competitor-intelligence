Deploy the WHOLE project on Render (no Vercel)
===============================================
The frontend now deploys on Render too, as a fourth service in the
same Blueprint. 15 files: 1 new, 14 modified. No npm install needed.

APPLY
  Extract this zip over your project folder
  (C:\Users\barnw\Downloads\competitor-intelligence\) and choose
  "Replace the files in the destination" for all. Restart both
  servers if they are running. Local behaviour is unchanged — the
  localhost URLs pass through untouched.

WHAT CHANGED
  render.yaml — new service `competitor-intelligence-frontend`
  (Next.js web service, `npm run start`). The Blueprint now creates
  4 services: frontend, API, worker, Redis. NEXT_PUBLIC_API_URL is
  wired automatically from the API service; FRONTEND_URL is
  pre-filled with the frontend's expected URL.
  frontend/services/apiUrl.ts — NEW. One helper every service file
  now uses: it turns the API URL into a full URL, adding https://
  when Render gives a bare hostname.
  frontend/services/*.ts (api, auth, competitors, scans, changes,
  analysis, battlecards, dashboard, jobs, integrations) — all read
  the API URL through that helper now.
  backend/src/config/env.ts — FRONTEND_URL gets the same treatment
  (bare hostname → https:// origin) so CORS works with the
  Render-wired value.
  backend/DEPLOYMENT.md + README.md — the guide now covers the
  all-on-Render flow; every Vercel step is gone.

DEPLOY (you do this in the Render dashboard)
  1. Push the project to GitHub (Render deploys from a repo).
  2. Render → New → Blueprint → connect the repo → fill in the
     secrets it asks for (MongoDB URI, JWT secret, Groq key, etc. —
     see DEPLOYMENT.md for the full list).
  3. After the first deploy, check the frontend service's URL. If
     it is not https://competitor-intelligence-frontend.onrender.com,
     set FRONTEND_URL to the real URL on the API + worker services
     and redeploy them.
  4. Open the frontend URL, register, add a competitor, Scan now.

FREE-TIER NOTE: both web services (frontend + API) sleep after
~15 minutes without traffic, so the first load after sleep takes
30–60 seconds. That is expected, not a bug.
